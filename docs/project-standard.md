# The project folder standard

A project is a folder in Cherry's list: one you opened or created (ADR-0032). Cherry
**extends cctop's `_project/` convention** instead of inventing a new one, so cctop's Projects
tab, its session hook and its project-notes skill keep working on the same files.

## Layout

```
~/Projects/atlas-api/
├── CLAUDE.md                 committed  front door for Claude, short, points to docs
├── README.md                 committed
├── docs/                     committed  engineering documents
│   ├── prd.md                the Plan stage's documents (V3, docs/v3-redesign.md):
│   ├── trd.md                technical requirements
│   ├── architecture.md
│   ├── data-model.md
│   ├── api.md
│   ├── roadmap.md
│   ├── test-plan.md
│   ├── specs/                one spec per round of work (Plan stage)
│   ├── issues/               one file per issue (Issues stage, ADR-0035)
│   │   └── 0001-chat-scroll-jumps.md
│   └── adr/
│       ├── 0001-use-sqlite.md
│       └── 0002-no-auth-in-v1.md
├── design/                   committed  the Design stage (V3): brief.json, tokens.css,
│   ├── screens/              one HTML file per screen (the canvas, r7)
│   ├── references/ assets/ system/ components/   files from the Brief (ADR-0050)
│   └── handoff/              written by Approve design (r9)
├── src/ ...                  committed  the code
└── _project/                 ignored    via .git/info/exclude (cctop standard)
    ├── STATUS.md             where we left off, next steps (cctop format)
    ├── project.json          app metadata: phase, repo, stack, doc paths
    ├── tasks.json            the phase task graph (from Core's preset)
    ├── survey.json           every question asked and the answer chosen
    ├── notes.md              personal notes (Notes & Tasks tab)
    ├── sessions.json         written by the cctop hook, never by hand
    └── log.md                written by the cctop hook
```

**The split:** engineering documents are part of the product, so they are committed. Working
state is personal, so it stays out of git. `_project/` is added to `.git/info/exclude`, not to
`.gitignore`, so nothing about it appears in the repo.

## States

When scanning, each folder is put in one state. Checks run in this order:

| Folder has | State | Badge | What the app does |
| --- | --- | --- | --- |
| `_project/project.json` (valid schema) | **Ready** | green | Opens straight into the workspace. |
| `_project/STATUS.md` only | **cctop** | blue | Opens the workspace; offers a light calibration. |
| neither | **Not calibrated** | amber | Shows the calibration prompt; nothing runs until approved. |

A `project.json` that fails validation is treated as **cctop** (if `STATUS.md` exists) or **Not
calibrated**, and the card shows a small "project.json has errors" note.

Skipped while scanning: dot-folders (`.cherry-worktrees`, `.Trash` …) and anything in
`config.json → scan.ignore`.

## Stages (ADR-0034)

Work goes round a loop of six stages, each with its own agent and chat in Cherry:

`plan` → `design` → `preparation` → `development` → `deployment` → `issues` → `plan` …

There is no "current stage" to keep up to date: the user opens whichever stage they work in.
Agents hand work to each other through the files above: Plan writes `docs/prd.md` or
`docs/specs/<name>.md` and the roadmap; Design writes the design and architecture docs;
Development builds and ticks the roadmap; Deployment writes the CHANGELOG and runbook; Issues
writes `docs/issues/`, which feeds the next Plan. `project.json → phase` is an old field: it is
still written by calibration and the survey but no longer shown or used.

## Issue files (ADR-0035)

`docs/issues/NNNN-short-name.md`, numbered from 0001:

```markdown
---
title: Chat scroll jumps on reply
status: open        # open | planned | done
type: bug           # bug | improvement | idea
severity: annoying  # blocks | annoying | cosmetic
cycle:              # the spec that took it, e.g. docs/specs/chat-polish.md
github:             # the GitHub issue URL once sent or imported
---

What happened, steps to reproduce, what was expected, where.
```

## `CLAUDE.md` template

Under about 80 lines. Generated by the survey or calibration from this template:

```markdown
# CLAUDE.md — {{name}}

{{one paragraph summary}}

## Read first
- `_project/STATUS.md` — where we are. Always read this first.
- `docs/prd.md` — what we are building.
- Open other files in `docs/` only when the task needs them.

## Stack
{{stack lines}}

## Commands
{{install / dev / test / lint / build}}

## Rules
- Ask before editing files or running commands.
- Record every real choice as an ADR in `docs/adr/` (copy `docs/adr/template.md`).
{{project-specific rules from the survey, e.g. "No payments. They are out of scope."}}
```

## `STATUS.md` format (cctop)

Cherry reads these headings and must keep the format cctop writes:

```markdown
# STATUS — {{name}}

## Where we left off
One short paragraph.

## Next steps
- [ ] First thing
- [ ] Second thing

## Done recently
- 2026-10-07 — Finished the Living Room floor and the HUD.

_Updated: 2026-10-08 14:10_
```

- The **Where we left off** paragraph feeds the workspace status block and Home card.
- The first unchecked **Next steps** item is the "Next:" line on cards.
- **Update status** asks Claude to rewrite this file from the session, shown as an edit approval.

## ADR format

`docs/adr/NNNN-kebab-title.md`, numbered from 0001, never renumbered. Template in
[`adr/template.md`](adr/template.md). Status is one of `Proposed`, `Accepted`, `Rejected`,
`Superseded by NNNN`.

Optional header lines used by the Decisions tab (ADR-0026):

- `- **Proposed by:** Claude (chat)`: Claude wrote the proposal with `propose_decision`.
- `- **Done:** not yet` on an Accepted ADR: approved, but the change is not made yet. Cherry
  writes the date (`- **Done:** 2026-10-15`) when it is made. An Accepted ADR without this line
  counts as done.
- `- **Rejected because:** …` on a Rejected ADR. The file stays as a record.

| Decisions tab | Status line | Done line |
| --- | --- | --- |
| Pending | Proposed | none |
| Approved | Accepted | `not yet` |
| Done | Accepted or Superseded | a date, or none |
| Rejected | Rejected | none |
