Software is more than code.

A chat with an AI goes straight to code. Real teams do not work that way. They write down what the client needs, agree on a plan, draw the screens, build it in small tested steps, check it, and ship it with a runbook. Each step is reviewed before the next one starts.

Cherry gives Claude Code that process. Each stage has its own agent with its own persona, skills and documents. The documents are files in your repo, so the next agent, a client, or you in six months can read them.

Seven rooms. One process.

A stage opens when the one before it is signed off: by your client on a client project, by you on a personal one.

Every stage is a room.

The agent's chat in the Claude Code look on one side, its documents on the other: a plain version for the client, a technical one for the next agent.

Plan

Decisions you can read later.

The architect writes the architecture, the data model and the roadmap. Every real choice becomes an ADR card: the options, the trade-offs and a recommendation. You approve, discuss or reject it.

Design

Screens before code.

The designer draws real HTML screens on a canvas: phone and desktop, light and dark, every state. Add references, a design system, colours and fonts in the brief. Sign-off writes the handoff for Development.

Development

A prototype first. Then the build.

The Development Team builds a clickable prototype and waits for your approval. Then it builds the rest, tests first, checks it in the browser, and hands it to Testing. Code, terminal and version control are one tab away.

Testing

Tested like someone else wrote it.

QA runs the test plan, opens the app in Chrome, logs bugs as issues and writes a summary in plain words with an acceptance list for you to try. Client documents export as a PDF.

A crew in every room.

Each room has specialist agents and skills of its own. The staff agent hands them the work, the way a lead asks a reviewer.

  • Required checks. Design needs an accessibility check, Development a code review, Testing a security review. A stage cannot be marked ready until they ran.
  • Job hints. After each message Cherry names the skills and specialists that fit the job. Plain word matching, no model call.
  • The Crew tab. See who ran, on which model, and what fits the last message. A click puts the request in the message box; you send it.

From a real run

A seven-day history for a small web app, through all seven rooms on Sonnet. The accessibility specialist found five problems in the design. Development wrote the tests first and ran two reviewers on its own. QA's security review cleared the release.

A closer look.

Built to be trusted with your code.

Loopback only

The daemon binds 127.0.0.1. Every request needs a session from a one-time login link.

Nothing without a yes

Edits and commands wait for your approval, or run in Auto mode when you choose it. Serious commands always ask with a warning.

Secrets stay closed

.env files, keys and credentials are never read. File tools cannot leave the project.

Easy on your plan

Every model call starts from your click. Meeting, hints and change summaries cost no tokens.

Install in two minutes.

Linux today. You need Claude Code signed in, git, and mise or Node 22 with pnpm. The GitHub CLI is optional.

The repo also ships a Claude Code skill, so Claude can install and run Cherry for you. 

git clone https://github.com/syedmehedihussain/cherry.git
cd cherry
mise install && pnpm install
./scripts/install-cli.sh
cherry
